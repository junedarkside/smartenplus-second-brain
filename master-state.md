**Bug 1 — pickup box showing when contract has no `pickup_point` enabled (contract `o7lfBSOenh`, dropoff-only).** Root cause: 4 spots in `components/forms/checkout/Passengers.js` read `contract.pickup_requires_zone`/`dropoff_requires_zone` (independent admin toggle) as the sole trigger for seeding/rendering/validating a pickup or dropoff field, without checking whether `pickup_point`/`dropoff_point` was actually enabled in `contract.info_fields` — two independently-settable admin controls that can drift out of sync (confirmed backend `operators/views.py:498` writes the zone flag with zero cross-check against `info_fields`, flagged as separate backend follow-up, not fixed this session). Fixed via a shared `isInfoFieldEnabled(contract, fieldType)` helper (added to `Passengers.js`'s existing `--- HELPERS ---` block) used at all 4 sites: initial seed (`useState` lazy init), rehydration seed, render (both `ZoneGatedField` and plain-textarea branches), and — the blocking one — the Yup `pickupZoneMatched`/`dropoffZoneMatched` validation `.test()`, which an Opus-model deep-review caught before ship: fixing only seed+render would have left checkout step 1 permanently stuck (unseeded `pickupZoneMatched` failing an ungated Yup check, no visible field to fix). Merged `develop @ fcee73ad` → `d9a85f93`.

**Bug 2 — Cart Summary sidebar + step-3 Confirmation showing a wrong/unrelated route** (e.g. "Bundhaya Resort, Ko Tarutao... → Hatyai Any Hotel" instead of "Hatyai Any Hotel → Pakbara Pier" for a general-transfer trip). Root cause: identical to a bug already fixed in `EnhancedTripCard.js` the day before (`5e21bffc`) — `isZoneBooking` in `CartDetailDisplay.js:79` and `TripsConfirmation.js:29` checked only "does this trip have a saved zone address," true for both real airport-transfer bookings AND general-transfer zone-pricing trips (which have no airport end). General-transfer trips got wrongly framed through the airport-style layout, pairing a typed address against a generic station-name placeholder. `TripsConfirmation.js:29` was actually the 3rd occurrence and the weakest — no `transfer_airport` guard AND no `serviceCategory`/transportation guard at all — found only via a dedicated Opus SWE-review pass against CLAUDE.md's REUSE FIRST rule, not the initial Explore. Fixed both by reusing the pre-existing `isAirportTransfer(contract)` helper from `helpers/airportTransfer.js` (zero new imports — both files already imported `getAirportEnd` from the same module) instead of hand-rolling a 4th divergent check. Verified `transfer_airport` is present on the cart-list API payload (`carts/serializers.py:110`) before shipping, so real airport bookings aren't silently broken. Merged `develop @ 709f4ba9` → `ba51c72b`.
